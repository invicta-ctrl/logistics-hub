# Claude Code adapter — optional tooling only
Shared authority is AGENTS.md and docs/CURRENT.md. The committed project setting selects kawing-orchestrator by default; merge into existing settings without replacing unrelated configuration. Preferred entry: Claude Desktop > Code > new local session > select the repository. CLI launch is optional; do not require it. Do not select workers as the main agent. Main model is owner-selected; never writes or executes shell; only delegates to the two named workers. Sonnet 5.5 (claude-sonnet-5-5) writes/executes; Haiku 5.5 (claude-haiku-5-5) reads/audits. Auditor cannot run commands; writer runs requested checks and supplies logs. No nested workers.
Before adoption check installed Claude Code supports custom main agents and Agent(type) allowlists; verify active agent, actual model availability, and no CLAUDE_CODE_SUBAGENT_MODEL override or provider/model allowlist fallback. The project sets CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1 (documented foreground override, including fork mode). The Agent pre-hook accepts explicit false, or an omitted run_in_background only when this environment setting is effective; rejects explicit background, unknown workers and overrides. The post-hook still requires completed status, exact pinned resolvedModel and no other modelsUsed. Post-call detection cannot undo writes already performed; stop, inspect and reconcile any mismatch. The hook requires supported exec-form command hooks and foreground Agent telemetry; verify Node is on PATH and runtime compatibility before adoption. Inspect effective settings and session metadata; if unavailable, ask owner. Smoke test: start a fresh local Desktop Code session with the orchestrator, invoke each worker for a bounded read-only task first, verify actual resolved model IDs, reject a third agent, deny main write/shell, deny auditor write/shell, and confirm writer can edit only authorized scope (repository/sandbox permissions still required). No unverified runtime guarantee: local/managed settings, CLI launch flags, model overrides and provider fallback can change behavior; this is a project adapter, not organization-level enforcement. Never use fallback models without approval. Sources: https://code.claude.com/docs/en/sub-agents ; https://code.claude.com/docs/en/settings ; https://code.claude.com/docs/en/hooks ; https://platform.claude.com/docs/en/models/overview .

## Required plugin bootstrap
SKILLS.md owns the universal capability policy. Shared settings enable the eight portable plugins and declare the verified non-default marketplaces; QMD is intentionally absent from shared settings. On owner-designated devices, use the existing user/local QMD install and verify its CLI and skill; on other devices do not install it automatically. First use the supported `claude plugin list --json` and plugin details/health diagnostics; check actual loaded skills and hooks. If missing or disabled, the Sonnet writer may use `claude plugin marketplace add <verified-source>`, `claude plugin install <verified-id> --scope project` (or user/local scope for owner-only QMD), and `claude plugin enable <verified-id>` with the correct installed scope. Review trust prompts and permissions; reload plugins or restart the session and recheck. Do not modify unrelated global settings. The Haiku auditor reads static guidance and reviews evidence only. No skill may spawn other workers or bypass model routing. See https://code.claude.com/docs/en/discover-plugins and https://code.claude.com/docs/en/plugins-reference .

## Default session on owner device
Install the three definitions into ~/.claude/agents and set agent: kawing-orchestrator in ~/.claude/settings.json, preserving unrelated settings. Restart Claude Code once after creating the directory. Ordinary fresh local sessions use the orchestrator without a CLI launch, subject to higher-priority settings and session overrides. Existing resumed sessions can retain their original agent. Project-local definitions/settings remain portable and may take precedence; keep them reconciled with the approved master kit. Do not blindly overwrite local differences. Verify actual startup agent and model telemetry in a fresh Desktop session. The environment switch also disables built-in Bash background tasks; for the localhost preview use a supported Desktop preview or explicitly managed owned local server process, never an unrelated process. If Desktop ignores the setting or completion telemetry is missing, stop before product writes; report actual runtime evidence rather than requiring a CLI or weakening model checks. The default applies to all user-level Claude projects, but Kawing governance adoption is only for authorized Kawing repositories.
