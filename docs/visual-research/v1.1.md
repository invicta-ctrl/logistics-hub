# V1.1 visual research and evidence: staff shell and navigation

Spec: `docs/specs/accepted/road-to-v2/v1.1-experience-foundation.md`. Screenshots are in `docs/visual-research/v1.1/`. They show demo accounts (Alex Reyes as Owner, Sam Cruz as Staff) and the public seed catalogue, never real staff.

## How the evidence was made

- I ran the real application, not a mock: a local Worker and D1 (`wrangler dev --local`) with every migration applied (`0001`–`0019`), the 397 seeded items, and an Owner and a Staff account.
- Baseline images come from V1.0 (`695f2db`, built from a detached worktree). After images come from this branch, rendered in Chromium through Playwright with reduced motion so frames are stable.
- Sizes: desktop 1440×900 (1×), tablet 768×1024 (2×), phone 390×844 (2×), and a 320×640 phone with root text at 200%.
- I inspected every image by eye, not only through DOM assertions. The findings below come from that inspection.

## Patterns adopted, and why they fit Logistics Hub

1. **Six sections in working order: Items, Stock, Loans, Self-Service, Activity, Administration.** These are the office's daily jobs (GOV.UK: "the most important top-level sections"). My account is no longer a section. It is reached from the avatar, where GOV.UK and most admin products put account links.
2. **Avatar menu for identity.** The avatar opens a native popover with the name, role and username, then My account, Public Lending Hub and Sign out. It needs no JavaScript to open or close: Escape and an outside click close it. Sign out and the Lending Hub link no longer take space in the bar.
3. **Phones: a four-tab bottom bar plus More.** Items, Stock, Loans and Self-Service are the jobs done at the counter with one hand. Five slots stay within M3's 3–5 limit. More opens the same account menu as a bottom sheet, with Activity and Administration (by role) added at the top. Each destination therefore has exactly one place in each layout. Labels are always shown (no icon-only tabs). The active tab gets an M3-style gold pill behind its icon. The Self-Service badge appears only when records need checking, which is critical information in Apple's terms.
4. **Focus never hidden by the bars.** `scroll-padding-top` and `scroll-padding-bottom` reserve both bars, following the WCAG 2.4.11 Understanding example. I checked that Chrome's own focus scrolling respects it: a control sitting behind the bottom bar is scrolled clear when focused. An end-to-end test also asserts that the last control clears the bar.
5. **Tokens.** I added these: `--radius-xl` and `--radius-pill`; `--shadow-lg` for menus (sm for resting, md for raised, lg for overlays); `--target` (44 px) and `--target-min` (40 px); `--bottom-bar`; `--safe-bottom`; and documented breakpoints (520 / 760 / 960 / 1180). Hard-coded `999px` radii and loose transition durations in `styles.css` now use the tokens. On touch screens (`pointer: coarse`), buttons, chips, view tabs and icon buttons get 44 px targets.
6. **Motion.** The motion is light and uses CSS only. The account menu drops in under the avatar, or slides up as a sheet on phones. It uses transitions with `@starting-style` and `allow-discrete`, so a second tap mid-animation simply reverses it. On each section change, the current-section marker grows from its centre and the page fades in over 160 ms. Only `transform` and `opacity` animate. Nothing blocks input. Everything is off under `prefers-reduced-motion`; the existing global rule covers that.
7. **Plain words.** "Inventory" became Items wherever the screen describes what an item is. "Stock & Pantry" became Stock, and Pantry stays a tab inside it. The item form's "Inventory settings" section became "Stock settings". Stock areas display as "General stock" and "Pantry"; the stored values `Inventory` and `Pantry` are unchanged. "Self-service" is spelled Self-Service throughout the staff UI. `/staff/inventory` redirects to `/staff/items` (301) and keeps its query, so saved links to an item still open it.

## Patterns rejected

- **Hamburger-only navigation on phones.** V1 already showed the cost: Activity and Administration sat off-screen in a sideways-scrolling strip. A hamburger hides all four daily jobs behind one tap.
- **Putting Activity or Administration in the bottom bar.** Six or seven slots break the 3–5 guidance and squeeze the labels until they can't be read.
- **A floating "New item" or "Lend" button.** It would compete with the bottom bar for the same thumb zone and risk hiding focus. Each page's primary action stays in its header.
- **A navigation rail on tablets.** At 768 px all six text links fit in the top bar, so a rail would only take content width.
- **View Transitions, spring motion or an animation library.** They aren't needed for these small changes. The spec forbids heavy dependencies, and cross-document transitions would become a hard dependency.
- **Copying the M3 auto-hidden labels or Sortly's visual style.** Staff need the labels, and the HAU USC oxblood and gold identity stays.

## Independent review

A read-only review agent went through the whole diff and found no blocking defect. I acted on what it raised:
- **Browsers without the Popover API (iOS before 17).** The avatar and More now fall back to showing and hiding the menu. The motion rules are written against `:not(:popover-open)`, so those browsers drop them and show the menu plainly.
- **The menu stayed open** when someone chose the page already shown, and while the next page loaded. Choosing any menu link now closes it at once (an end-to-end test covers the same-page case).
- **Phone scroll padding** applied even to public pages without a bottom bar. It is now scoped with `html:has(.app-nav)`. The bottom-bar padding on `.app-main` is likewise skipped when the bar is absent, as on the forced password change.
- **The menu's right offset** used `100vw`, which includes a desktop scrollbar. It now uses `100%`.
- **Leftover copy:** "No self-service activity this week" became "No Self-Service activity this week".
- **Not changed:** below 1100 px the ID column, and with it the ID sort header, is hidden, as on phones in V1. Sorting by ID on a tablet is gone; search still finds IDs, and the ID shows under each name.

## Accessibility observations

- **Landmarks and names.** The header holds `nav` "Sections", then `main`. The More and avatar buttons both report `aria-expanded`. The avatar button's accessible name begins with "Account:" and contains its visible text (label in name). The Self-Service count is announced as "…, N records to check".
- **Keyboard.** Every section, More, the avatar and every menu entry is reachable by Tab. Escape closes the menu. `aria-current="page"` appears in the nav and in the menu.
- **Targets.** The bottom bar is 64 px tall with five equal columns. Menu items are 44 px on phones and 40 px on desktop. Coarse pointers get 44 px controls.
- **Focus not obscured.** Handled with scroll padding for both bars; see adopted pattern 4.
- **Large text.** Covered by the 320 px / 200% render above, plus the existing 320 px end-to-end checks. Known limit: at 200% text on a 320 px phone, the bottom-bar labels shorten to "It…", "St…" and so on. Icons and accessible names stay intact.
- **Reduced motion.** Every animation and transition sits behind `prefers-reduced-motion: no-preference`. The existing global reduce rule clamps anything else.

## Performance

I measured with Playwright against the two local Workers, using the same database. Each figure is the median of 7 runs, desktop, cache cleared before each cold load.

| | V1.0 (`695f2db`) | V1.1 |
|---|---|---|
| Cold load of the staff home to first item row (run 1 / run 2) | 289 / 254 ms | 250 / 240 ms |
| In-app switch Items → Stock, click to heading (run 1 / run 2) | 108 / 102 ms | 118 / 118 ms |
| JS + CSS transferred, uncompressed | 163.7 KB | 170.8 KB |

Build output: the main CSS grew from 61.2 KB (11.6 KB gzip) to 66.8 KB (12.6 KB gzip), and the staff chunk from 67.0 KB (21.6 KB gzip) to 68.0 KB (22.0 KB gzip). No dependency was added. The section switch is consistently about one frame (10–16 ms) slower, probably from the extra shell markup (the menu and nav icons) re-rendered on every switch; I did not profile it further. The 160 ms page fade runs after the content is already in place and doesn't block input. I judge this not a meaningful regression; cold load is not slower.

**Then, section code is loaded ahead.** Pointing at, touching or tabbing to any in-app link now starts loading that page's code (one delegated listener in `src/main.ts`; the module cache makes repeats free). I re-measured with a 150 ms hover before the click, which is how people actually use the bar:

| Median of 7 | V1.0 | V1.1 |
|---|---|---|
| Items → Stock switch, local | 81 ms | 78 ms |
| Items → Stock switch, slow network (150 ms latency, 1.6 Mbps) | 384 ms | 208 ms |
| Cold load to first row, slow network | 884 ms | 902 ms |

On school Wi-Fi-like conditions a section change is now about 45% faster than V1.0. The cold-load difference is within noise.
