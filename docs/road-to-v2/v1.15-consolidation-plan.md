## Owner amendment: mobile-first and perceived-performance pass (Earl, 2026-10-07)

Earl strengthened V1.15 with a finalization pass. It adds acceptance criteria and checks; it adds no feature and no framework, and all accepted V1.15 scope stays. **No V1.15 implementation starts until V1.14's gate is met.** That includes the dead-export removal in the findings below, which is held. It is recorded as an accepted amendment, on Earl's "yes" of 2026-10-07: `docs/specs/accepted/road-to-v2/2026-10-07-v1.15-mobile-perceived-performance-amendment.md`, referenced from the V1.15 spec.

Intent: V2 must feel immediate, not only benchmark fast. Mobile is the primary acceptance target and desktop second.

**Ownership.** V1.14 stays authoritative for the performance architecture: D1 and query efficiency, bounded APIs, DOM, storage and queues, Cloudflare use and scale tests. After V1.14 completes, V1.15 inherits its measured budgets and must not regress them. A remaining bottleneck that a V1.15 journey exposes is repaired as a V2 quality defect with the smallest measured fix, and no speculative performance infrastructure is added.

**Mobile-first widths.** Check about 320, 360, 390 and 430 px first, then tablet, then desktop. Look for clipping, overlap, sideways overflow, offscreen or unreachable actions, bad wrapping, small touch targets, broken tab layouts, awkward dialogs and sheets, unsafe-area problems and uneven spacing. Desktop must use the room cleanly without looking sparse or stretched.

**Perceived performance.**
- Draw the stable page shell and geometry at once; never leave an unexplained blank region.
- Content-shaped skeletons only on a true first load. After valid content is shown, keep it during a refresh instead of swapping in a loader.
- Load primary data before secondary metrics and media. Optional panels fail on their own and never block the page.
- Images reserve their size and load lazily and asynchronously.
- Reuse what exists (intent-based route warming, request de-duplication, ETags, failure isolation) rather than building a second system.
- Every interaction gets an immediate visual acknowledgement. Durable writes (stock, loans, audits, accounts, system settings) may show a working state at once, but show success only after the server has committed.
- Privacy audit before any new persistence or caching. Official staff IDs, private evidence and other restricted data are never cached persistently for speed.

**Interaction completeness.** For every route, list each visible control. Each must be reachable, named, usable and uncovered at phone and desktop sizes, and either exercised by a fixture-safe browser test or covered by a V2 journey. No dead button, dead tab, placeholder action or unexplained disabled control remains.

Design decisions (smallest durable):

1. **No migration.** Resolve and Ignore are written as `audit_log` rows on the Self-Service record (a new reviewed-identity action in the Activity vocabulary); the Attention reason lists records with a missing or invalid identity that have no such row. `idx_audit_log_entity_item` already serves that lookup. If the lookup is not bounded at scale, V1.15 asks V1.14 for a migration number (V1.14 may claim 0031 for a closed-loans index) and does not take one on its own.
2. **Strict Student ID applies to new Self-Service records only.** `STUDENT_ID_PATTERN` stays as it is for the Staff Directory and staff-entered loans, so no historical record is rewritten or made unreadable. A queued offline record from an older phone that reaches the server without a valid identity is accepted once, idempotently, and shown in Identity needs review; it is not refused, because that would lose evidence.
3. **Linking needs no new data.** Takes and Uses carry the Student ID from now on, so the existing exact-ID rule links them. A first name with an exact ID links and also appears in Identity needs review. Two directory people with the same ID cannot exist (the column is unique), so matching cannot be ambiguous.
4. **Historical formats are not yet checked in production.** The production read was refused, so the shapes of existing IDs in `staff_directory`, `loans` and `self_service_events` are unknown to me. This does not change the design above (it never touches old rows) but decides how many existing staff records will link to a new 8-digit entry. Earl is asked to allow a shape-only count or run it himself.

### Acceptance checklist added by the amendment

Each line needs evidence (a test, a measurement or a screenshot I have looked at) before V1.15 is called complete.

- [ ] No major route shows a blank loading screen.
- [ ] Layout stays put while data arrives (no visible shift).
- [ ] Useful content is kept during a background refresh.
- [ ] Core workflows work when optional data or media fail.
- [ ] Every interaction acknowledges at once; no durable write claims success before the commit.
- [ ] No material clipping or sideways overflow at 320, 360, 390 and 430 px, nor on tablet and desktop.
- [ ] Touch targets, dialogs and sheets are usable on phones, including unsafe areas and large text.
- [ ] Nothing restricted is persistently cached; privacy audit recorded.
- [ ] V1.14's budgets hold.
- [ ] Interaction inventory complete for every route, each control tested or covered by a journey.
- [ ] One tab and segmented-control style; accent only for the active state; light and dark contrast checked.
- [ ] Public and staff wording cleaned, sentence case, no enum names, no "verified" claim for ordinary students.
- [ ] Self-Service: Take, Use, Borrow and Return each need name, 8-digit ID and photo; server rejects bad IDs with browser checks bypassed; offline, remembered-profile and retry cases pass.
- [ ] Directory linking by exact ID (including first-name-only); wrong name cannot redirect; no name-only staff linkage.
- [ ] Identity needs review: appears, Resolve and Ignore work, both audited, no duplicate after resolution, original text kept.
- [ ] `/staff/activity` is a full-height workspace: bounded page, own scroll region, pagination in the region, phone and desktop natural, no DOM growth.
- [ ] Added Take and Use photo storage and upload cost measured against the V1.14 Cloudflare model.
- [ ] `docs/visual-research/v1.15.md` covers phone, tablet and desktop, and first load, warm navigation, refresh, slow network, empty, error, offline and reduced motion where they apply, from screenshots I have inspected.

The recommended default is to keep "Catalog" for the app and section, rename the page to **Add items** (Home and search already call it that), and keep "cataloguing" as the verb.
