## What changed

- **Fixed (test):** the Worker end-to-end test for the photo menu treated a menu that was still fading out as open, so it failed on slow runners right after Back. It now reads `:popover-open` and no longer retries (`tests/worker-browser/worker-live.spec.ts`).
- **Changed (defensive):** a popover menu that is closing takes no presses while it fades or slides away (`src/styles.css`, `.menu[popover]:not(:popover-open)`).
  - Chromium already skipped a closing popover when hit-testing. This was measured with `elementFromPoint` at desktop width and at 390 px, so no failure was observed there; other engines were not tested.
  - The no-Popover fallback menu, which has no `popover` attribute, is unaffected.
