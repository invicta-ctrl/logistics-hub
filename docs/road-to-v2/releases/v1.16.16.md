## What changed

| Principle | Change | Files |
|---|---|---|
| MUJI, Linear (spec §3 "one status") | A phone Items row shows one status, the most urgent (out of stock, then warnings, then Inactive, then pending, restock, listed), with a quiet "+N" for the rest. On phones (a list narrower than 26rem, so up to 430px) the status takes its own line under the name and reference instead of the column beside the quantity. Before this, two status tags took the second column, the name was squeezed into about 80px and wrapped to three lines, and "ITM-0107 ·" broke across lines. The other statuses are clipped to one pixel, so screen readers still read them; desktop and the sheet show every status as before. "Unclassified" yields a tie, because the row's sub-line already names the type. | `src/staff.ts` (`tags()`), `src/styles.css` (the 44rem container block) |
| Linear (board 08) | The item sheet's facts are a ruled key-value list: the label beside its value, with hairlines between rows, instead of a three-column grid. Same facts, same order. | `src/staff.ts` (one class), `src/styles.css` |
| Framer | Pressing an Items or Stock row shows the open-row tint at once, so the tap is answered before the sheet arrives. It is a colour change, not motion, and it is the same under reduced motion. | `src/styles.css` |
| Airbnb | No visual change was needed. The Filters button already counts the active filters, and search, the filters and the count stay in one toolbar line. Removable filter chips are flow F5 in the proposed amendment. | — |
