## What shipped

- **Home:** search first, then **Return** and **My activity**, then four items from each group (**Equipment**, **Supplies**, **Pantry**) with **See all N**. Groups are derived from the catalog's own action and stock area (`groupOf`), so staff keep nothing extra. The phone's most used items come first as **Used often**. Four cards across from 48 rem; two on a phone. A group opens as a light list with chips between groups.
- **Search** matches name, other names and place, every word typed; "Nothing matches" in words.
- **The item's page:** picture, group and how it is used, how many are available, one sentence saying what will happen (the item decides Take, Borrow or Use, never the person), where it is kept with **Where is it?**, one action. A card morphs into it with the View Transitions API (skipped for reduced motion). An item no longer offered says so.
- **Who you are:** asked once, with **Remember me on this phone** a visible choice; afterwards a card with **Not you? Change**; **Forget me on this phone** in My activity → This phone.
- **Check before you send** for every action (item and quantity, who, what for, return date, the photo that will be sent), with **Confirm** and **Edit**. Nothing is saved before Confirm. Policy unchanged: Borrow and Return need a photo; Take and Use need a name; individual borrowing needs name and student ID; USC use needs name and reason.
- **Receipt** with a reference `SS-XXXX-XXXX` (derived from the event id, no schema change) and honest state ("Saved on this phone" / "Synced with Logistics"). Staff find a record by reference, name, ID or item in **Self-Service → Last 7 days**; reference and photo link also appear on review cards.
- **My activity:** **On loan now** (with **Return**, return date, late note), **waiting to send** with **Send now**, **Recent** with references, **This phone**.
- **Contextual help:** one toggletip component (`src/contextual-help.ts`) beside the student ID, the photo and remembering you.
- **Catalog snapshot** gains `area` (`Pantry` or `Inventory`). Everything else about the queue, events, sync, service worker and manifest shortcuts is unchanged.
- **Catalog intelligence amendment (§11 item, Rules A–G on the screens this slice rebuilt):** Self-Service keeps one term per concept (Take, Borrow, Use, Return; **Saved on this phone**, **Waiting to send**), no redundant Borrow/Take choice, and the help component follows rule C (only beside terms that need it).

## Known limitations

- Kits are not offered in Self-Service (a kit's readiness is staff knowledge).
- The reference is derived from the event id, so it is 40 bits and not guaranteed unique; staff also see name, item and time. Older records also show a reference, because it is computed from the id, not stored.
- A catalog snapshot saved before this release has no `area`, so its non-Borrow items show in Supplies until it refreshes.
- The staff reference search covers the last 7 days, the same window as that view.
- Real phones, a real camera and screen readers were not tested; the evidence is Chromium with device emulation and a drawn stand-in photo.
- Two worker-browser tests fail in this container only (see Verification).
