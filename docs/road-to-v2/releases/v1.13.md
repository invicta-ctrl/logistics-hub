## System health: what is read, and how

| Row | How it is checked | A failure says |
|---|---|---|
| Application | the request itself reached the Worker; the build's identifier comes from `dist/build.json` | (the page would not load) |
| Database | `SELECT 1` on D1, timed | "Not answering" |
| Loan photos, Catalog pictures, Staff ID scans | `get` of a key that is never stored on each R2 binding, timed (nothing written, nothing listed) | "Not answering" |
| Self-Service | the stored setting (`selfServiceState`) | "Unknown" if unreadable |
| Migrations | `d1_migrations` (wrangler's table) against the migration list in the build record | names what is pending; "could not be read" if the table or record cannot be |
| Build, commit | `dist/build.json`, validated field by field (12-hex version, ISO time, migration names, a full 40-hex commit or null) | "No version is shown" / "Not recorded" |

- **Bounded and cheap.** All checks start together and each is cut at two seconds (`PROBE_LIMIT_MS`), so the page waits at most about two seconds and a hung bucket cannot hang it (test: a bucket that never answers is reported not answering at the limit). The report is made only when the System section is opened or **Check again** is pressed; no other staff page, no polling and no background job calls it. `GET /api/staff/admin/system` is `private, no-store` and for ADMIN and OWNER only.
- **Nothing is assumed.** A probe's error text never leaves the function (only the check's name is logged); the answer carries `ok`, milliseconds, labels and what each bucket holds. A failure of the whole report shows a plain error state instead of a blank page, and the other sections do not depend on it.
- **Trustworthy build identity.** `build.json` is emitted by the same Vite build as the assets of the same deploy, so it can only describe the code that is answering. The commit is recorded only when the environment states a full 40-character hash (`WORKERS_CI_COMMIT_SHA`, or `GITHUB_SHA`); a local build says "Not recorded". The public `/build.json` is 404 (`run_worker_first` is on and the route returns 404), and the Worker reads it through `env.ASSETS`.
- **Backup and restore evidence: none is shown, deliberately.** A run's backup and Time Travel bookmark live in GitHub's Production operations artifacts and the key is held offline by the owner; the application holds no Cloudflare or GitHub credentials, so it cannot verify either, and the spec forbids fabricating them. The page says so and points to the runbook. If a safe source appears later (for example a manifest of the last backup written by the lane itself) it is a small addition to this section.
- **Local evidence** (throwaway Worker, `docs/visual-research/v1.13/timings.json`): the System report answers in a median of 17 ms (seven runs); the System page draws its first row in a median of 107 ms (five runs). Cold load to the first Items row 289 ms and an Items → Stock switch 64 ms in the same run, so navigation did not move.

## Decisions

- **No editable D1 knowledge overlay.** The amendment allows one "only if a concrete need is shown". None was: nobody has asked for an organization-specific hint that other names (per item, editable now) cannot express, the hints are small and shipped (28 entries), and an overlay would add a table, a migration, a second source of truth next to `KNOWLEDGE` and a rules editor the amendment says not to build. Other names cover the real need: finding an item by the word people use.
- **No migration, so `0031` stays with V1.12's numbering.** The migration level is read, never written.
- **The AI panel is static.** It says "Not connected" and what the section will show if it is ever connected. It shows no call count, cap or breaker state because none exists; showing zeros would be a fabricated reading.
- **"Classified from a suggestion" is not recorded**, so the Catalog section shows classification coverage and "classified at capture" (from `catalogue_captures`) and says plainly that the other figure does not exist.
- **Static explanatory tables became label/value lists.** Backups, phone rules, the role guide and the hints have no sortable data, and the shared mobile table rules broke them on a phone (`docs/visual-research/v1.13.md`, defect 4).
- **Confirmations are sheets, not `window.confirm`**, for the reasons in the research: they can say what changes, name the action and keep focus on the safe choice.
- **No new deployment platform, no auto-migration, nothing destructive**: the production boundary is untouched.
