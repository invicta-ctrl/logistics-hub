## What shipped

- **Global search** for the staff workspace: **Search** in the top bar (an icon on phones, no new bottom-bar slot) and **Ctrl+K** / **⌘K**; `/` stays the page's own search. A modal dialog with an APG combobox and grouped results: Go to, Places, Kits, Items and, for administrators, Staff Directory. Every row says what it is, why it matched and where it is kept; an ID opens its record; a few fixed words open existing pages ("overdue" → Attention's overdue loans). Nothing in search changes a record. (`src/search-palette.ts`, `.css`, `src/staff.ts`.)
- **Deterministic matching** over names, other names, categories, places (and every place above), kits and V1.8 knowledge-base kinds, with exact-over-prefix weights, a reason per result, and one hop along explicit links and kit membership from a clearly meant item (`src/search.ts`).
- **The staff search index** `GET /api/staff/search` (`src/search-index.ts`): items, places, kits, components and links in one revisioned read, ranked in the browser; typing reads nothing from D1.
- **People search for administrators** `GET /api/staff/admin/directory/search` (`findPeople`): ranked in the Worker, at most 8 and the total, `private, no-store`, with **See all N in the Staff Directory**.
- **Item links** (migration `0030`, `src/item-relations.ts`, `src/relation-policy.ts`, `src/item-links-panel.ts`): Used with, Alternative to, Replaced by / Replaces, Holds / Goes in, from both ends, at most 20 per item, audited (`ITEM_LINKED` / `ITEM_UNLINKED`, shown in Activity), shown on the item's record as **Linked items**.
- **The Workers AI boundary, not the feature** (`src/catalog-ai.ts`, `evaluateWithAi` in `src/suggest-evaluation.ts`, `--ai` in `scripts/evaluate-suggestions.mjs`): see "Workers AI second opinion" below.
- **Small fixes on the way:** an item, kit or place sheet keeps focus on Close when it redraws (focus had fallen to the page); at 200% text on a 320 px phone the brand mark gives way so the bar fits; a V1.9 help-note test that failed about half the time under load now waits for layout (12 of 12 and 33 of 33 runs).

## Search and index design

Full design: `docs/GLOBAL_SEARCH.md`. In short: one lean, revisioned index of the catalog's searchable words, sent once per catalog change (a 304 reading one row otherwise) and ranked in the browser per key; people ranked in the Worker per pause, for administrators only, a handful at a time. No KV, Vectorize, embeddings, external search service or new binding. Weights: name 10/8, other name 8/6, kit 6/5, place 5/4, category 4/3, kind 3/2 (exact/start); every word must match; ties break by one numeric, case-insensitive collator, so the same words always list the same way; at most 50 per kind with the true total.

## Workers AI second opinion (amendment §13)

**Decision.** Earl chose **Measure first** on 2026-10-07: build only the payload boundary and a fixture measurement, run it with the account's credentials, and build the runtime feature only if it helps. This session has no Cloudflare credentials, so **the measurement with the model has not been run**, and V1.11 adds no binding, endpoint, setting or UI. With nothing to switch on, the §13.6 tests "setting off" and "on while the provider fails" have no runtime to test; the measurement's own failure path is tested (a failing provider counts every call as failed and stops at its limit).

**What exists.** `src/catalog-ai.ts` is the single payload builder: the typed name (120 characters), up to 8 other names (60 each) and the live category, unit and behaviour option lists (deduplicated, sorted, the "unsorted" placeholder removed), nothing else. An answer is kept only when a value is exactly one of those options; anything else, including an unreadable reply, is no suggestion. An answer is at most Weak and reads "AI suggestion". `tests/catalog-ai.test.ts` (7) proves the allowlist (a record full of `SECRET` fields sends none of them; the measurement hands the model only payloads), the exact-option filter, the failure path, and that no `ai` binding exists and only the measurement imports the module.

**Measured so far (built-in only, 254 confirmed fixture items, knowledge base v2):**

| Field | Strong (right) | Weak (right) | Conflicting (either right) | None |
|---|---|---|---|---|
| Behaviour | 81 (75%) | 92 (67%) | 14 (93%) | 67 |
| Unit | 65 (94%) | 89 (80%) | 38 (89%) | 62 |
| Category | 103 (93%) | 77 (84%) | 13 (100%) | 61 |

So a second opinion could only matter for the 61–67 items per field with no suggestion and the Weak and Conflicting ones. `--ai` adds, for each of Weak, Conflicting and None, how often the model answered, how often it was right, and how often either was right. Without credentials it prints "Nothing was sent." and exits 1 (checked).

**Model and cap (from official Cloudflare documentation, 2026-10-07).** `@cf/ibm-granite/granite-4.0-h-micro`: in the live catalog, on Workers Free, no licence step, 1,542 / 10,158 Neurons per million input / output tokens, about **1 Neuron per call** (250 in, 60 out). Workers Free and Paid both include **10,000 Neurons a day** per account, reset at 00:00 UTC; Free stops at the limit, Paid bills overage at $0.011 per 1,000 Neurons, and calls from local `wrangler` sessions count too. The recommended cap if built: **1,500 calls a day** (about 15%, inside V1.14's green band). Sources: [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) (updated 2026-10-01), [limits](https://developers.cloudflare.com/workers-ai/platform/limits/), [models](https://developers.cloudflare.com/workers-ai/models/), [planned deprecations](https://developers.cloudflare.com/changelog/post/2026-05-08-planned-model-deprecations/) (Llama 3.1 8B and others were retired on 2026-05-30), [JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/), [errors](https://developers.cloudflare.com/workers-ai/platform/errors/).

**Privacy and logging.** Cloudflare's [data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/) page (updated 2026-04-21): inputs and outputs are Customer Content, not used to train models without consent and not shared with other customers. **No retention period is stated (unverified).** Whether JSON mode is enforced for this model is unverified, which is why the answer is checked in code. ## Known limitations

- **Near-identical names list shorter ones first.** A name with fewer extra words ranks higher, so "Archive Box 106 - Receipts 2022" comes before "Archive Box 002 - Liquidation Reports 2018"; within the same length the order is numeric.
- **At ten times today's catalog it is still fast; at twenty it is noticeable.** A keystroke's p95 is about 11 ms at 5,000 items and about 32 ms at 10,000 on this machine; a slow phone may be several times slower. The next step, if ever needed, is ranking in a Web Worker, measured first.
- **People search reads the whole directory table per request** (96 people in production; measured at 600 in 3 ms). It answers 8.
- **After opening a page (not a sheet) from search, focus lands on the page body**, as it does for the navigation links before V1.11. Sheets put focus on Close.
- **No recent searches, favourites or learned ranking**, on purpose (privacy and predictability).
- **The Workers AI second opinion is not built** (Earl's decision; owner action 2).
- Pre-existing, unchanged by V1.11: at 768 px with 200% text the top bar runs past the screen edge (also on V1.10).
- Real D1 latency, real phones, a screen reader and a Windows run were not tested.
