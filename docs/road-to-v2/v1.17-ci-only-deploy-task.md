## Goal

One normal production deploy path (V116-QH03). The GitHub `Deploy` workflow deploys a commit on `main` only after its CI, its exact-source CodeQL and the read-only migration gate pass. Cloudflare Workers Builds stops deploying `main` by itself and keeps its repository link and preview builds. The manual deploy and the audited rollback stay as the owner's exceptional operations.

## Today (2026-10-16)

- Workers Builds deploys each push to `main` about a minute after the push, before CI finishes.
- `Deploy` runs after every green CI on `main` as a dry run that uploads nothing (`DEPLOY_FROM_CI=dry-run`). On `6ceefb5`, Deploy `38774572920` passed every gate. A commit made by GitHub's merge button is refused at the combined-CodeQL gate (`8754ffb`, Deploy `38762253186`), so after this switch such a merge would not deploy.
- Cloudflare's Workers Builds check runs on public commits link to the dashboard with the account id in the address, and its production builds of `main` also list the new Worker version id. These come from Cloudflare's integration, not from this repository's workflows. Turning off the automatic deploys of `main` stops those version ids; preview builds keep the account id link.

## Scope

Two settings, both changed by Earl, and one proof deploy:
1. In Cloudflare, turn off the automatic deploys of the production branch `main` for Worker `logistics-hub`. Keep the repository connection and preview builds.
2. In GitHub, change the repository variable `DEPLOY_FROM_CI` from `dry-run` to `true`.
3. Prove one CI deploy: re-run the latest green CI on `main`, or merge the next qualified change.

No application code, data, migration, binding, token or account change belongs to this task. If the token lacks a permission it needs, stop and record BLOCKED_EXTERNAL; do not create or widen a token.

## Tests

Each test needs a receipt in this task's record before the task is done.
1. **Preflight, before any change:** main protection read back (strict `checks` and `worker-e2e`, combined `CodeQL`, administrators included, no force push or deletion); `DEPLOY_FROM_CI` reads `dry-run`; the latest `Deploy` dry run on `main` passed every gate; no migration is pending; the token in the `production` environment has Workers Scripts: Edit and D1: Read; the active Worker version is captured privately as the rollback target.
2. **One deploy, from CI:** exactly one `Deploy` run deploys the exact `main` commit. Every gate passes, and its public log shows only the curated "Deployed <commit> (ci)" line.
3. **No second path:** the new `main` commit gets no Workers Builds production build, and production changes version once.
4. **Live check:** the live assets match a local build of that commit, and Administration > System shows the expected version and commit.
5. **Refusals stay in place:** the gate and workflow tests in `tests/deploy-gate.test.ts` pass. They refuse missing or unfinished CodeQL results, a pending or unreadable migration list and a deploy target that is not a commit, and they check that only a curated status is shown.

## Rollback

Stop merging. Set `DEPLOY_FROM_CI` back to `dry-run` and let any running `Deploy` finish, then turn Workers Builds' automatic deploys of `main` back on. Never have both on. If a bad version went live, roll back to the captured version in Cloudflare or with the `Deploy` workflow's audited rollback. No data or migration is involved. Turning Workers Builds back on reopens QH03.

## Approval gate

After the preflight passes, Earl approves the two settings changes and the proof deploy explicitly, in the thread that runs this task. He makes the settings changes himself; agents do not change Cloudflare or GitHub settings. The task is done only with every receipt above and his confirmation. Until then, production stays on the Workers Builds path.

## After the switch

Merge only by fast-forwarding `main` to a checked head. A merge-button commit lacks the combined CodeQL check, so the gate refuses it and production keeps the previous version. A merge goes live once CI finishes, about 10 to 12 minutes after the push, instead of about a minute.
