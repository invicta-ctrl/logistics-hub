## Objective
Rebuild the Self-Service experience around visual discovery, clear item identity, location guidance and consistent accountability while preserving the proven offline queue and transaction invariants.

## Start gate
Fetch latest main, verify V1.8 completion, safely rebase, and confirm item media, locations and kit foundations are healthy.

## User experience
Self-Service should feel like a fast consumer app rather than a database form. The typical flow is **Search/browse → recognize item → view item → find it → transact → confirm → receipt**.

## Scope
1. Redesign Self-Service home with prominent search and visually organized groups such as Frequently used, Equipment, Office Supplies, Pantry and Kits where available.
2. Use item photos and compact cards without turning long catalogs into heavy galleries. Show key information only: name, availability, category/type cue and concise location.
3. Add a full Self-Service item page with image, availability, plain-language behavior, **Where is it?** and one correct transaction action. Users must not choose between technical TAKE/BORROW/USE modes; item configuration decides.
4. Establish consistent identity for applicable outgoing Self-Service transactions: full name and Student ID are required according to the accepted policy, with a **Remember me on this phone** profile and clear **Not you? / Change** action. Do not create a public identity database from remembered local details.
5. Require contextual photo evidence for outgoing/return actions according to the accepted accountability design. Keep evidence private to authorized staff, separate from public catalog media, and governed by existing retention/privacy rules.
6. Add a polished confirmation step summarizing item, quantity, identity, evidence and return information before submission.
7. Add human-readable transaction references in receipts while preserving immutable internal IDs.
8. Redesign My Activity around currently borrowed items, recent activity and pending offline records. Sync implementation details should stay quiet when healthy.
9. Preserve offline-first behavior: transactions save locally first, photos queue safely, users get clear offline/queued states, and synchronization does not block normal interaction.
10. Integrate kits only where V1.8 established complete semantics. Do not fake whole-kit borrowing if component accounting is not complete.
11. Improve Self-Service staff review presentation as needed to make the new identity/evidence records reviewable, but keep broad Attention automation for V1.10.

## Motion and visual quality
Use fast photo/card/detail transitions, sheet/dialog motion and success feedback. Prefer native/CSS/View Transition APIs where supported. Motion must never delay transaction saving or hide state changes and must respect reduced motion.

Create `docs/visual-research/v1.9.md`. Research current mobile commerce/catalog discovery, lending/library flows, camera evidence UX, confirmation/receipt patterns and PWA/offline messaging. Use current internet references and document principles, not copied branding.

Capture and visually inspect home, search, category/group, item page, location viewer, identity setup, borrow/take/use forms, photo capture/preview, confirmation, receipt, My Activity, return and offline states at phone sizes plus tablet/desktop. Run complete realistic journeys and iterate based on actual screenshots.

## Acceptance criteria
- A first-time user can find and complete a valid transaction without knowing inventory terminology.
- Item behavior is derived from item configuration; no redundant Borrow/Consume choice appears when the system already knows.
- Identity/evidence requirements are consistent and validation is clear.
- Remembered identity reduces repeat typing and is easy to change/forget.
- Where-is-it works with the V1.4 location model.
- Confirmation/receipt flows prevent accidental submission and provide a useful human reference.
- Offline transactions, photos and returns remain reliable and understandable.
- Self-Service remains fast with 500+ catalog items and media.
- Required tests, worker/offline browser cases, build, privacy/retention checks, accessibility, visual evidence, migration/data verification and final diff review pass.

## Finish protocol
On `complete`/`finish`, satisfy all criteria and create `docs/road-to-v2/releases/v1.9.md` with `STATUS: COMPLETE`, final commit, migrations, privacy/evidence notes, end-to-end transaction/offline evidence and visual review. Integrate only when green.

## Exclusions
No Staff Directory changes, universal Attention center, global command search, operations dashboard or predictive intelligence beyond what Self-Service directly requires.
