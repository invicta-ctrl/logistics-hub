## Objective
Create a fast global discovery layer that lets staff find items, locations, kits and authorized staff records using ordinary terms, while keeping normal search deterministic, local/fast and independent of AI services.

## Start gate
Fetch latest main, verify V1.10 completion and safely rebase.

## Scope
1. Add a global search/command surface available from the staff shell; on desktop support a shortcut such as `Ctrl/Cmd + K` where it does not conflict with browser/platform behavior.
2. Search authorized domains with clear grouping: Items, Locations, Kits and Staff Directory records according to permissions. Loans/actions may appear when they have a clear authorized navigation target.
3. Improve item matching using normalized item names, aliases, categories, location terms, kit relationships and explicit purpose/compatibility tags where these have a current use.
4. Support relationship types that make discovery smarter without opaque inference: Alternative, Replacement, Commonly used together, Kit component and related location context.
5. Example behavior: searching `sewing` can find a Sewing Kit and related sewing items; searching a cabinet can find the location and its items; searching an authorized staff name can open that staff profile.
6. Add lightweight intent shortcuts only where deterministic, such as `overdue` opening the relevant loan/attention filter. Do not build a speculative natural-language command framework.
7. Keep private domains permission filtered at the query/API level, not merely hidden in the UI.
8. Design indexing/query strategy for realistic 500+ item scale and future growth without introducing an unnecessary external search service.
9. If optional AI-assisted search is explored, it must be asynchronous/optional, never required for core search and never receive private data without explicit accepted authority. No AI dependency is required for this slice.

## Visual research and rendered review
Create `docs/visual-research/v1.11.md`. Research current command palettes, omnibox/global search, grouped result UIs and inventory/catalog discovery. Record sources, useful patterns and rejected patterns.

Capture and inspect screenshots for empty/default command palette, mixed grouped results, no results, loading, keyboard navigation, mobile global search, permission-limited results and relationship-driven item discovery. Test with realistic catalog scale and long names.

## Performance/accessibility
- Search should feel immediate for common queries and must not materially slow page startup.
- Keyboard navigation, screen-reader result announcements and focus management are mandatory.
- Avoid shipping the full private Staff Directory into public/client caches merely to power search.

## Acceptance criteria
- Global search finds the supported authorized object types reliably.
- Results respect permissions server-side/API-side.
- Aliases, relationships, locations and kits improve useful matching without opaque guesses.
- Keyboard command/search flow works end-to-end and mobile has an equally understandable entry point.
- Search remains responsive at realistic data size and does not require external AI.
- Required tests cover ranking/matching boundaries, permissions and navigation; build, privacy scan, browser/E2E, accessibility, performance evidence, visual evidence and final diff review pass.
