## Objective
Create one coherent operational attention model so Logistics Hub automatically surfaces the records that deserve staff action while keeping normal records quiet. Automate derived states and boring follow-up work without turning the product into a noisy alert system.

## Start gate
Fetch latest main, verify V1.9 completion and safely rebase.

## Principles
- Attention is a derived cross-system concept, not a second ledger or a manual status users must maintain.
- The system should surface concrete reasons and direct next actions, not vague severity scores.
- Automation must never silently mutate authoritative stock, approve evidence, punish users, or infer misconduct.

## Scope
1. Define a bounded Attention domain/API that can aggregate actionable states from Items, Stock, Locations, Loans, Kits, Self-Service and catalog completeness without duplicating source truth.
2. Initial attention reasons include where supported by existing data: overdue loan, damaged/lost return, low/out stock, unresolved physical-audit discrepancy, repeated can’t-find/location report, kit needing replenishment, catalog record missing required photo/location/classification, offline sync conflict and review-needed Self-Service record.
3. Attention entries resolve automatically when their underlying condition is resolved, while preserving relevant audit history where needed.
4. Add compact attention indicators/counts in the staff shell and contextual surfaces without introducing an overwhelming notification system.
5. Add an operational Attention view/inbox with filters by reason/source, age and urgency where urgency can be objectively derived. Each entry must link directly to the record/action needed.
6. Automate follow-up state where deterministic: damaged return marks the item/loan for review, kit component shortage changes kit readiness, catalog completeness clears when completed, resolved location discrepancy clears its attention item, etc.
7. Introduce background/precomputed derivation only where it materially improves speed; do not require a language model or external AI call.
8. Keep notification delivery in-app for this slice. External email/push escalation remains excluded unless already necessary to complete an accepted workflow.

## Visual research and rendered review
Create `docs/visual-research/v1.10.md`. Research current task inbox, issue triage, operations console and notification-center patterns. Prefer products that distinguish actionable work from passive activity. Record sources and reasons.

Capture and visually inspect attention badges, inbox/list, empty state, grouped reasons, mobile/detail interactions and contextual resolution. Seed realistic mixed conditions and make sure the design is calm rather than alarm-heavy. Use the agent’s screenshot/vision review.

## Performance
Attention calculations must not make normal navigation noticeably slower. Prefer indexed/derived queries or bounded background refresh. Measure relevant page/API latency before and after and document any meaningful change.

## Acceptance criteria
- Attention reasons are derived from authoritative existing state, not manually duplicated.
- Resolving source conditions clears corresponding active attention correctly.
- Staff can understand why an entry exists and navigate directly to the next useful action.
- No attention automation silently changes stock, staff identity, loan history or evidence outcomes.
- The inbox works at realistic data volume and does not slow normal app use materially.
- Mobile/desktop presentation is coherent and visually reviewed.
- Required tests cover derivation/resolution and permissions; build, privacy scan, browser/E2E, accessibility, performance evidence, migration verification and final diff review pass.

## Finish protocol
On `complete`/`finish`, satisfy all criteria and create `docs/road-to-v2/releases/v1.10.md` with `STATUS: COMPLETE`, final commit, attention rules, performance evidence, migrations, automated-resolution tests and visual evidence. Integrate only when green.

## Exclusions
No external email/push campaign system, user risk scoring, misconduct prediction, global command search, operations dashboard or predictive procurement.
