## Objective
Give staff a calm operational home that answers “What should I do next?” and surfaces useful insights from existing authoritative data without becoming a chart-heavy executive dashboard.

## Start gate
Fetch latest main, verify V1.11 completion and safely rebase.

## Scope
1. Add a staff home/landing surface that summarizes actionable work from the V1.10 Attention model, current/resumable sessions and role-appropriate quick actions.
2. Example sections: **Needs attention**, **Continue**, and **Quick actions**. Keep counts meaningful and link directly to filtered workflows.
3. Support resumable work such as an unfinished cataloguing or physical-inventory session when one genuinely exists.
4. Add practical operational insights only when they answer a staff question, such as commonly borrowed equipment, frequently used consumables, repeat stock-out patterns, locations generating repeated find/location reports, kit replenishment frequency and catalog completeness.
5. Insights must be explainable and based on current authoritative data with explicit time windows. Avoid opaque “AI scores” or recommendations with no supporting reason.
6. Any restock/usage suggestion should show the evidence behind it and remain advisory. No automatic procurement or stock mutation.
7. Personalize only harmless workflow shortcuts/preferences where appropriate; do not infer hidden user traits. Role and recent explicit workflow may influence quick links.
8. Keep heavy analytics queries off the critical navigation path. Precompute/cache bounded summaries where useful and measure impact.
9. Use the global search/command layer from V1.11 as an optional fast entry point rather than adding duplicate navigation systems.

## Visual research and rendered review
Create `docs/visual-research/v1.12.md`. Research current operations dashboards, task-oriented home screens, admin start pages and lightweight analytics patterns. Prefer examples that prioritize action over decorative charts.

Capture and inspect screenshots for staff with no attention items, busy realistic state, resumable session, mobile/tablet/desktop, different roles and insight cards. Review visual hierarchy so urgent/actionable work is obvious without making the app feel alarming or cluttered.

## Performance/accessibility
The home screen must load quickly and should not block staff from navigating if an insight query fails. Measure API/render timing and keep expensive summaries bounded/asynchronous where possible.

## Acceptance criteria
- Staff landing page clearly communicates actionable work and next steps.
- Attention counts and links match authoritative V1.10 state.
- Resume links only appear when there is valid resumable work.
- Insights include time-window/context and are explainable; no automatic procurement or opaque scoring.
- Role/permission boundaries are respected.
- Failure of optional insight data does not break primary operations.
- Responsive layouts are visually reviewed and remain calm/scanable.
- Required tests, build, privacy scan, browser/E2E, accessibility, performance evidence, visual evidence and final diff review pass.
