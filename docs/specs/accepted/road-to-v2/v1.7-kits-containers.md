## Objective
Make real USC groupings such as Sewing Kits, supply kits and Arts & Crafts Kits first-class operational objects without duplicating or weakening the underlying item, stock and loan truth.

## Start gate
Fetch latest main, verify V1.6 completion and safely rebase.

## Domain rules
A kit is a structured composition of existing inventory items/components. Components retain their own stock/loan behavior and ledger truth. Kit status should be derived from component state where practical instead of manually maintained.

## Scope
1. Add kit definitions with name, optional photo, description, location, active status and component requirements.
2. Allow kit components to mix loanable items, whole-unit consumables and gradual-use/open-unit consumables.
3. Support quantities/required minimums per component and derive states such as Ready, Needs replenishment and Needs review from current component data.
4. Add Kit Templates for repeatable groups such as Sewing Kit and Arts & Crafts Kit. Creating another kit from a template should avoid rebuilding contents manually while keeping each physical kit’s state distinguishable when needed.
5. Add a Check kit workflow optimized for quick verification: component checklist, missing/low/damaged observations and completion summary.
6. A kit check must not silently alter underlying stock; actual corrections/replenishment follow existing movement/count rules.
7. Integrate relevant expiry/reorder information from components when already available so time-sensitive supply kits can surface components needing attention.
8. Add kit profile UI with visual component status and clear links to underlying item records.
9. Make kit membership available to Catalog/Rapid Catalogue workflows in a practical way without turning every catalog operation into a kit workflow.
10. Keep Self-Service exposure conservative in this slice. If current public surfaces show kits, they must only expose behavior that is fully complete in V1.7; otherwise staff-only operation is acceptable until V1.8.

Capture and visually inspect kit list/profile, ready/incomplete states, template creation, check-kit flow, mobile/tablet checklist and completion summary. The agent must review rendered screenshots for hierarchy, component scanability and clear distinction between kit status and actual item stock.

## Acceptance criteria
- Staff can create/edit/deactivate kits and define mixed-behavior components.
- Templates can create repeatable kit structures without duplicating stock truth.
- Check-kit workflow is fast, auditable and does not silently mutate inventory.
- Derived kit readiness changes correctly when relevant component state changes.
- Kit UI remains understandable on phone/tablet/desktop.
- Existing item/stock/loan invariants remain intact.
- Required tests, migrations/data verification, build, privacy scan, browser/E2E, accessibility, visual evidence and final diff review pass.

## Finish protocol
On `complete`/`finish`, satisfy all criteria and create `docs/road-to-v2/releases/v1.7.md` with `STATUS: COMPLETE`, final commit, migrations, component/ledger verification, template/check evidence and visual evidence. Integrate only when green.

## Exclusions
No full Self-Service kit borrowing redesign, Staff Directory, universal Attention center, intelligent global search or predictive replenishment beyond directly derived kit/component state.
