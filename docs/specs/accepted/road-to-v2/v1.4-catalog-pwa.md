## Objective
Create a dedicated staff-only Catalog PWA experience for physical cataloguing in the DOL office, including explicit offline-readiness behavior and built-in Android/iOS installation guidance. This slice establishes a usable offline-capable catalog workspace even before Rapid Catalogue arrives.

## Start gate
Fetch latest main, verify V1.3 completion, and safely rebase. Stop if the predecessor is incomplete.

## Product boundary
`Logistics Catalog` is a focused mode/app surface of the same Logistics Hub product and backend, not a second independent database or duplicated architecture.

## Scope
1. Add an authenticated staff-only Catalog entry point optimized for phone/tablet use during physical inventory work.
2. Add installable PWA metadata/icon/start-route behavior as needed without breaking the existing Self-Service PWA. Choose a clean architecture for separate/related install experiences and document the decision.
3. Staff must authenticate online before enabling offline catalogue access on a device. Do not store a reusable plaintext password.
4. Introduce a bounded, expiring offline authorization/lease suitable for safe cataloguing work. It must be revocable/expirable and scoped to permitted catalogue operations, not broad Administration powers.
5. Define offline-capable operations for this foundation: view cached catalog/location data needed for field work, create/update local catalogue drafts, capture item/location photos for queued upload, and preserve draft state through reload/restart where supported.
6. Offline work is queued and clearly marked. It must not silently become server-authoritative until synchronization succeeds.
7. Provide a clear readiness state such as **Ready for offline cataloguing**, including storage/caching checks and useful failure guidance.
8. Build in installation instructions and device detection:
   - Android/Chrome: use browser install prompt when available; otherwise guide Menu → Install app / Add to Home Screen as supported.
   - iPhone/iPad: guide user to open in Safari → Share → Add to Home Screen → keep Open as Web App enabled where shown → open once online → wait for Ready for offline cataloguing.
   - Keep copy current by validating against current browser/platform guidance during implementation.
9. Add safe service-worker/update handling so a new Catalog version does not destroy unsynced local work.
10. Establish a clean local data model/API boundary for later Rapid Catalogue and physical-inventory sessions without implementing those later workflows now.

## Security and privacy
- Offline authorization must be minimally scoped and time-bounded.
- Local cached data must avoid unnecessary private staff/personnel data.
- Private evidence/USC IDs are not part of this PWA foundation.
- Sign-out/lease expiry must behave predictably without deleting unsynced work accidentally; define a safe resolution path.

## Visual research and rendered review
Create `docs/visual-research/v1.4.md`. Research current installable PWA patterns, offline status/readiness UI, field-data collection apps, iOS/Android install guidance, and mobile inventory/cataloguing products. Prefer web.dev/MDN/platform docs for technical behavior plus polished field-work products for interaction references.

Capture and visually inspect Catalog landing, install flow, online/offline states, readiness states, queued draft indicator and tablet/phone layouts. Validate actual installation behavior on representative Android-like Chromium and iOS guidance paths where tooling permits; do not approve install UX from code alone.

## Acceptance criteria
- Authorized staff can open the Catalog experience while normal users cannot.
- Catalog can be installed as intended without breaking Self-Service PWA behavior.
- Online authentication can enable a bounded offline-capable session.
- Catalog reopens offline with the required cached shell/data and can preserve allowed drafts/photos.
- Unsynced work survives expected reload/service-worker update cases.
- Android and Apple installation guidance is built into the product and visually verified.
- Offline/online/readiness states are understandable without developer terminology.
- Required tests include worker/service-worker/offline browser cases, security checks, build, privacy scan, accessibility, visual evidence and final diff review.

## Finish protocol
On `complete`/`finish`, finish all criteria and create `docs/road-to-v2/releases/v1.4.md` with `STATUS: COMPLETE`, final commit, security model, offline lease behavior, install evidence, verification and visual evidence. Integrate only when green.

## Exclusions
No Rapid Catalogue session workflow, bulk categorization, physical inventory session, kits, Staff Directory or Self-Service 2.0. Do not overbuild future synchronization semantics beyond what V1.4 needs.
