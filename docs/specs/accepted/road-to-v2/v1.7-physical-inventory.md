## Objective
Turn the Catalog PWA into a practical physical-audit tool. Staff should be able to choose a location, verify what should be there, pause/resume, record discrepancies and finish with a safe review instead of manually hunting through 500+ records.

## Start gate
Fetch latest main, verify V1.6 completion and safely rebase.

## Scope
1. Add **Inventory by Location** using the reusable location model. A session selects a location and loads the items expected there.
2. Track progress such as `31 / 38 verified`, with clear states for confirmed, quantity mismatch, not found, moved/unknown and review-needed.
3. Allow pause/resume across reload/device-offline cases where safe. Sessions must have durable identifiers and timestamps.
4. Physical observations do not silently rewrite quantity. At session completion, produce a discrepancy review and require proper count/movement posting through existing ledger rules.
5. Preserve observed evidence and reasoning when a later count reconciles a discrepancy. Do not rewrite history.
6. Track useful data freshness: last physical count, last location verification, unresolved discrepancy and verification age. Prefer derived presentation over duplicated manually maintained state.
7. Support location-photo/direction review during an audit and allow a staff report when a stored location needs correction.
8. Ensure the workflow remains usable offline under the V1.6 offline authorization and queue model and the V1.5 session model, with clear conflict handling when server state changed while the device was offline.
9. Add a concise completion summary suitable for handoff/audit evidence.

## Visual research and rendered review
Create `docs/visual-research/v1.7.md`. Research current cycle-count/stocktake interfaces, checklist/progress patterns and mobile field-audit apps. Record sources and reasons for adopted/rejected patterns.

Visually test phone/tablet/desktop states for session start, progress, verified item, mismatch, not-found, paused/resume, offline, conflict and completion summary. Run a realistic multi-item session and inspect screenshots with the agent’s vision for scanability, accidental taps and progress clarity.

## Acceptance criteria
- Staff can start, pause, resume and complete a location-based inventory session.
- Expected items and session progress are correct and remain performant at realistic scale.
- Observations never bypass movement/count invariants.
- Completion produces a discrepancy review rather than silent stock mutation.
- Offline sessions sync/reconcile without destroying evidence or overwriting newer authoritative data.
- Last-verification/count information is trustworthy and understandable.
- Required tests, browser/offline cases, migration/data verification, build, privacy scan, accessibility, visual evidence and final diff review pass.
