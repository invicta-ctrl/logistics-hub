# Accepted amendment — V1.15 Mobile-first and perceived-performance finalization

STATUS: ACCEPTED BY OWNER (Earl, instruction of 2026-10-07, "Owner amendment / strengthened V1.15 acceptance direction"; recorded in the repository on his "yes" the same day)
APPLIES TO: `docs/specs/accepted/road-to-v2/v1.15-v2-consolidation.md` (scope, V2 acceptance criteria, final visual review)

## Decision

V2 must feel immediate, not only benchmark fast. Mobile is the primary acceptance target and desktop second. V1.15 adds this finalization pass to its accepted scope. It adds no feature family and no framework, and every earlier V1.15 requirement stands. V1.15 implementation does not begin until the V1.14 predecessor and start gate is satisfied.

## Requirements

1. **Mobile first.** Review every major screen, tab, button, link, input, filter, menu, dialog or sheet, text treatment, and loading, error and offline state at about 320, 360, 390 and 430 px first, then tablet and desktop. Find and fix clipping, overlap, accidental horizontal overflow, offscreen or inaccessible actions, bad wrapping, undersized touch targets, broken tab layouts, awkward dialogs and sheets, unsafe-area problems and inconsistent spacing or hierarchy. Desktop uses the available space cleanly without becoming sparse or stretched.
2. **Perceived performance.** Render the stable shell and page geometry immediately; never leave an unexplained blank region. Use content-shaped skeletons for true first loads only. Once valid content is shown, keep it while refreshing instead of replacing it with a loader. Load primary data before secondary metrics and media. Optional panels fail independently. Images reserve their dimensions and load lazily and asynchronously. Keep using the existing intent-based route warming, request de-duplication, ETags and failure isolation rather than building duplicate infrastructure.
3. **Immediate acknowledgement.** Every interaction gets an immediate visual response. Durable writes (stock, loans, audits, account and system changes) may show a processing state at once, but success is shown only after the authoritative server commit. Authoritative writes are never faked.
4. **Privacy before persistence.** Audit privacy before any new persistence or caching. Official staff IDs, private evidence and other restricted information are never persistently cached for perceived performance.
5. **Interaction completeness.** For every major route, inventory the visible interactive controls. Each is reachable, named, usable and uncovered at phone and desktop sizes, and is either exercised by a fixture-safe browser test or covered by a realistic V2 journey. No dead button, dead tab, placeholder action or unexplained disabled control remains.
6. **Performance ownership.** V1.14 stays authoritative for performance architecture, D1 and query efficiency, bounded APIs, DOM, storage and queues, Cloudflare resource use and scale testing. After V1.14 completes, V1.15 inherits its measured budgets and must not regress them. A remaining bottleneck that a V1.15 journey exposes is repaired as a V2 quality defect with the smallest measured solution; no speculative performance infrastructure is added.
7. **Visual audit.** `docs/visual-research/v1.15.md` also covers phone, tablet and desktop, and first load, warm navigation, refresh, slow-network or loading, empty, error, offline and reduced-motion states where they apply. The renders themselves are inspected; code inspection alone is not evidence.

## Added V2 acceptance criteria

- No major route shows a blank loading screen.
- Layout is stable while data arrives.
- Useful content is kept during a background refresh.
- Core workflows do not depend on optional data or media, and keep working when those fail.
- Interactions acknowledge immediately.
- No material mobile overflow or clipping.
- V1.14's budgets are preserved.

## Exclusions

No framework, new feature family, speculative caching or performance infrastructure. Prefer deletion, consolidation, existing primitives, bounded caching and simpler request and render flows.

The working checklist, route inventory and journey matrix for this amendment are in `docs/road-to-v2/v1.15-consolidation-plan.md`.
