# Road to V2 — V1.14 Offline, Performance & Reliability Hardening

STATUS: ACCEPTED BY OWNER FOR IMPLEMENTATION
ROADMAP: Road to V2
VERSION: V1.14

PREDECESSOR: `docs/road-to-v2/releases/v1.13.md` with `STATUS: COMPLETE` on `main`

## Objective
Stress and harden the entire Road-to-V2 product under poor connectivity, large catalogs/media, concurrent use and real mobile constraints while preserving the polished visual experience and the speed of normal workflows.

## Start gate
Fetch latest main, verify V1.13 completion and safely rebase. Capture current production-like performance/offline baselines before changing behavior.

## Scope
1. Exercise all offline-capable flows under deliberate network loss/reconnect: Self-Service, Catalog PWA, Rapid Catalogue and physical-inventory sessions.
2. Test interruption cases including reload/app restart, service-worker update, queued photos, low storage/quota pressure, authorization lease expiry and reconnect during sync.
3. Test concurrent/multi-device state changes and human-readable conflict handling. Never silently overwrite newer authoritative state or discard local evidence.
4. Review queue idempotency/retry behavior so reconnects or repeated sync requests do not duplicate transactions.
5. Test catalog scale and image scale using realistic fixture volume (500+ items plus media), large Staff Directory data and attention/search workloads.
6. Establish measured performance budgets from the V1.13 baseline for startup, route transitions, common API calls, search, large lists and image-heavy surfaces. Fix regressions and record justified exceptions rather than relying on subjective “feels fast”.
7. Audit asset delivery: image variants, lazy loading, cache policy, service-worker cache size/eviction, font/CSS/JS weight and layout shift.
8. Audit animations and view transitions for jank on representative mobile conditions. Motion must degrade gracefully and never hold application state changes hostage.
9. Harden install/update flows on Android/Chromium and iPhone/iPad guidance. Preserve unsynced data through update where architecturally possible and provide clear recovery guidance otherwise.
10. Perform a cross-product accessibility stress pass: keyboard, focus restoration, large text, reduced motion, color/contrast, screen-reader names, touch targets and orientation/responsive changes.
11. Review security/privacy implications of offline caches, private R2 URLs, Staff Directory media, remembered Self-Service identity and authorization leases.

## Visual and external-reference review
Create `docs/visual-research/v1.14.md`. Re-check current web.dev/MDN/platform guidance for service workers/PWAs/performance, current accessibility guidance and current motion/performance practices. Record source dates and any changes from earlier assumptions.

Capture and inspect representative degraded-state screenshots: offline, reconnecting, conflict, queued media, storage warning, update-ready, reduced-motion and narrow/large-text layouts. Visual polish must remain understandable under failure states, not only on ideal screens.

## Acceptance criteria
- Offline-capable workflows survive tested interruptions without silent data loss.
- Sync/retry is idempotent for covered transaction classes.
- Conflicts preserve both evidence and current authoritative state and present understandable next steps.
- 500+ item/media fixtures remain responsive within documented budgets.
- Images, caches and service-worker behavior are bounded and do not grow without control.
- Common animations remain smooth enough under representative conditions and reduced-motion paths work.
- Android/iOS install/update guidance is revalidated.
- Privacy/security review finds no unintended private-media/public-cache exposure.
- Full relevant unit/integration/browser/offline tests, build, privacy/secret scan, accessibility, performance evidence and final diff review pass.

## Finish protocol
On `complete`/`finish`, satisfy all criteria and create `docs/road-to-v2/releases/v1.14.md` with `STATUS: COMPLETE`, final commit, measured baseline/after results, offline/conflict matrix, cache/media findings, security/privacy results, known limitations and visual evidence. Integrate only when green.

## Exclusions
No major new product feature or architecture rewrite. V1.14 fixes/hardens what V1.1–V1.13 already built. Any new feature discovered during hardening requires an amendment rather than being smuggled into this slice.
