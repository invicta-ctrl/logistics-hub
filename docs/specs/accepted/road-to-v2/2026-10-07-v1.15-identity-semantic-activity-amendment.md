# Accepted amendment — V1.15 Mobile-first consolidation, semantic cleanup, Self-Service identity assurance and Activity layout

STATUS: ACCEPTED BY OWNER (Earl, instruction of 2026-10-07, "V1.15 Owner Amendment — Mobile-First V2 Consolidation, Semantic Cleanup, Self-Service Identity Assurance, and Activity UX")
APPLIES TO: `docs/specs/accepted/road-to-v2/v1.15-v2-consolidation.md`
BUILDS ON: `docs/specs/accepted/road-to-v2/2026-10-07-v1.15-mobile-perceived-performance-amendment.md` (its requirements stand; where this amendment is stricter or more specific it controls)

This is not a new feature family. It makes the finished V2 visually coherent, mobile-first, fast-feeling, semantically clean, accountable and easy to use. All data, accountability and privacy invariants stay.

## A. Mobile-first final audit
Mobile is the primary acceptance target, desktop second. Verify every major surface at about 320, 360, 390 and 430 px, tablet, normal desktop and large desktop: every tab, button, link, text block, title, subtitle, badge, filter, input, search box, card, table or list, menu, sheet or dialog, toolbar, and each empty, loading, error and offline state. No major surface ships with clipping, overlapping controls, accidental horizontal viewport scrolling, unreadable wrapping, hidden actions, awkward empty space, tiny touch targets or a control that works at only one width. Visual quality is never approved from code inspection alone.

## B. Product-wide clutter and text cleanup
Apply the semantic-minimization doctrine across the public landing page, Lending Hub, Self-Service PWA, staff sign-in, Home, Items, Stock, Loans, Activity, Attention, Catalogue, Kits, Locations, Staff Directory, Administration, search, and sheets and major secondary states. Remove redundant helper paragraphs, obvious instructions, labels that say the same thing twice, internal or database terms, exposed enum names, unneeded technical status, excess copy around obvious controls, and decoration that competes with the main action. Keep contextual help only for ambiguous, technical, policy-sensitive or consequential concepts. Public wording is the simplest: Borrow, Take, Return, Available, Where to find it, Your name, Student ID number, Photo proof, Needs staff review. Sentence case throughout unless a proper name requires otherwise. Text hierarchy: page title > important state or action > section title > body > helper text > metadata. Clutter is not solved by shrinking text.

## C. Typography, tabs and colour
One tab and segmented-control system: inactive neutral and quiet; hover and pressed subtle; active an unmistakable product accent; keyboard focus a strong accessible ring; counts and badges subordinate to the label; success, warning and error colours reserved for semantic states, never navigation decoration. No arbitrary per-tab colours. Light and dark keep sufficient contrast. Use existing design tokens, not page-specific colour values. The product reads as one application.

## D. Perceived performance
As in the earlier amendment, plus: refresh stale data in the background; primary content before optional metrics and media; never preload entire datasets to manufacture speed; reuse route warming, ETags, request de-duplication and bounded caching where appropriate; every tap acknowledged at once; no authoritative write shown complete before the server commits it. V1.14 keeps authority over real performance architecture, and V1.15 preserves its measured budgets.

## E. Self-Service identity
For every new Self-Service transaction by an Angelite student or USC staff or officer (Take, Use, Borrow and Return), require before confirmation: full name, Student ID number, and required contextual photo proof. There is no USC-use exemption: a USC transaction still identifies the person handling the item. Take and Use records must keep the Student ID. The confirmation screen shows the person's identity clearly before final submission. Remembering a person on this phone may reduce typing but does not weaken validation and stays local and private under the existing privacy policy. Photo proof remains private staff evidence and never becomes public catalog media. V1.14/V1.15 resource verification accounts for the added Take and Use evidence uploads and storage.

## F. Student ID format (new Self-Service records)
Exactly 8 decimal digits. Valid: `12345678`. Invalid: `1234567`, `123456789`, `12-345678`, `ABC12345`, `12A45678`, `1234 5678`. The field is `type="text"` with `inputmode="numeric"`, `pattern="[0-9]{8}"`, `minlength="8"` and `maxlength="8"` (never `type="number"`), prevents non-digit entry and paste where practical while staying accessible, and the Worker independently enforces `/^\d{8}$/`; client checks are never the authority. The shared `STUDENT_ID_PATTERN` is not changed globally before the existing records in `staff_directory`, `loans` and `self_service_events` have been inspected. Historical records are never rewritten or invalidated for being looser. If legitimate older formats must be kept, the strict rule applies to new Self-Service records and historical readability is preserved.

## G. Staff Directory usage linking
The Staff Directory Student ID is the authoritative cross-reference. Order: (1) exact normalized Student ID that matches exactly one Staff Directory person; (2) the name is supporting evidence only; (3) never a face or photo. An exact match automatically associates the applicable Self-Service usage and loan history with that person and shows it in the Directory's usage history, without requiring the submitted name to equal the full name ("Juan" with 12345678 belongs to Juan Dela Cruz, and also appears in Identity needs review because the name is incomplete). No fuzzy name-only staff linkage. No duplicated business truth when existing queries can derive the link from the Student ID; prefer the smallest durable implementation.

## H. Identity needs review (Attention)
A new Attention reason, **Identity needs review**, lists a Self-Service record when: the full name is missing or incomplete; the Student ID is missing; the Student ID is not valid under the new rule; a directory-linked Student ID carries a materially inconsistent submitted name; or a legacy or offline record reaches the server without the now-required identity. New online and offline records should normally be stopped by the form, so Attention is the recovery path for legacy, interrupted, malformed or inconsistent records, not a replacement for validation. An exact Student ID still links usage to the directory person while a name review is open. Staff resolve it with **Resolve / confirm identity** or **Ignore**; ignoring is a reviewed outcome, not deletion; both are audited; the text the person originally submitted is never overwritten.

## I. What is verified
An 8-digit format check proves only the format. An exact match to a Staff Directory person lets Logistics Hub verify and link that staff identity against its own directory. For ordinary students who are not in the directory, the interface and records must not claim the Student ID is institutionally verified; V1.15 builds no student database and no external integration.

## J. Activity workspace scrolling
`/staff/activity` stops growing the whole page. The shell, navigation and header stay stable and the workspace fills the remaining viewport. The feed is the main scroll region using the available height, not a small fixed box: the page does not grow with history; the feed has its own scroll (`min-height: 0`, `overflow: auto`); it allows for the mobile bottom navigation and safe-area insets; keyboard access, focus and natural touch scrolling hold; no double-scroll trap; search and filters stay reachable; cursor pagination stays bounded and loads older records inside the region; the full history is never in the DOM. On a phone it feels like a full-height activity screen. Other extremely long history panels are inspected for the same problem; no generic scrolling framework is made.

## K. Verification
Responsive and visual: systematic phone, tablet and desktop screenshots; no material clipping or overflow; consistent typography and tabs; public wording cleaned; light and dark; reduced motion; keyboard and focus; empty, loading, error and offline states.
Self-Service: Take, Use and Borrow each require full name, 8-digit Student ID and photo; Return keeps valid identity and requires a photo; wrong-length IDs and IDs with letters, dashes or spaces are rejected; the server rejects invalid IDs when browser validation is bypassed; remembered profiles are still validated; offline records keep identity and photo safely; sync and retry stay idempotent.
Directory linkage: an exact staff Student ID links to the right person; a first name with an exact ID still links; an incomplete name produces Attention; a wrong name cannot redirect usage when the ID matches; no fuzzy name-only staff linkage; students outside the directory remain ordinary transaction identities.
Attention: incomplete identity appears; resolve and ignore work; decisions are audited; no duplicate item after resolution.
Activity: bounded page shell; independent feed scroll; pagination works; natural phone and desktop scrolling; no uncontrolled DOM growth.
Performance and privacy: V1.14 budgets stay green; the added evidence upload and storage cost is measured; no private photo, identity or ID-card data becomes publicly cacheable; no new unbounded query or response; no speculative service or framework.

## Stop conditions
Stop and report instead of guessing if: legitimate production Student IDs conflict with the new format in a way that would corrupt or invalidate history; a migration becomes necessary without accepted migration and rollback authority; directory matching finds ambiguous duplicate Student IDs; the added photo requirement materially breaks the verified V1.14 Cloudflare and storage envelope; or an external student database or identity provider would be needed. Otherwise, once V1.14 clears the start gate, implement through verification without asking again.
