# Road to V2 — V1.2 Item Profiles, Media & Visual Identity

STATUS: ACCEPTED BY OWNER FOR IMPLEMENTATION
ROADMAP: Road to V2
VERSION: V1.2
BRANCH: `road-to-v2/v1.2-item-profiles-media`
PREDECESSOR: `docs/road-to-v2/releases/v1.1.md` with `STATUS: COMPLETE` on `main`

## Objective
Turn Items from table-centric records into recognizable digital profiles while introducing a durable media pipeline for catalog images. V1.2 must be fully useful on its own and must not depend on reusable locations or later Self-Service redesign work.

## Start gate
Fetch latest main. Verify V1.1 completion record exists and is included on main, then safely rebase this parked branch onto that main. If not, stop before implementation.

## Scope
1. Add one primary catalog/profile image per item, manageable by authorized staff from Items.
2. Store structured media metadata in D1 and image objects in R2; keep catalog media separate from private borrower/evidence media.
3. Support take/upload, preview, replace and remove flows with clear permissions and audit events.
4. Build an image-processing path appropriate to the current Worker/browser architecture: validate supported image types, normalize orientation, strip unnecessary metadata, generate/serve appropriately sized variants or thumbnails, and avoid shipping full-resolution originals in lists.
5. Redesign the item detail experience around a recognizable profile: primary image, name, availability, type/category, current location text if already present, status, and context-specific tabs/actions. Preserve stock, loan, edit and history functionality.
6. Introduce polished photo interactions. Clicking/tapping item thumbnails or profile images should open/expand smoothly using fast native/CSS/View-Transition capabilities where supported, with an instant accessible fallback and reduced-motion support.
7. Improve Items list/card presentation progressively while retaining efficient desktop scanning and existing filtering/sorting. Do not turn a 500+ item staff inventory into a slow image gallery.
8. Maintain lazy loading, reserved image aspect ratios and skeletons/placeholders to avoid layout shift.

## Visual research and rendered review — mandatory
Create `docs/visual-research/v1.2.md`. Research current item/product-profile patterns, image viewers, inventory/admin UIs and motion guidance using current web references. Prefer official design systems plus real catalog/inventory products. Record sources, useful principles, rejected patterns and performance implications.

Capture and visually inspect the real app at desktop, tablet and phone sizes for at least: Items list/table, item profile with image, image viewer, edit/upload state, missing-photo state. Compare against V1.1 baseline and iterate on visual defects. Use the agent’s visual capabilities; DOM/code assertions alone do not satisfy this gate.

## Performance/privacy requirements
- Catalog imagery may be viewable only where existing catalog visibility permits; borrower/evidence imagery must never be reused as catalog media.
- No staff/borrower PII or binary images enter public Git.
- Use thumbnails/lazy loading and measure page weight/loading impact.
- Do not introduce a heavy image or animation framework when browser/platform capabilities suffice.

## Acceptance criteria
- Authorized staff can add, replace and remove an item profile image end-to-end.
- R2/D1 media references remain consistent after replace/remove and failure cases.
- Items with and without photos render cleanly at all required responsive sizes.
- Item profiles preserve all existing stock/loan/edit/history workflows.
- Photo expansion/viewer feels polished, remains fast, supports keyboard/escape/back behavior where appropriate, and respects reduced motion.
- Lists with hundreds of items remain performant and visually stable.
- Visual research/screenshots are reviewed and documented.
- Required tests, build, privacy scan, browser/E2E, accessibility, migration verification if schema changes, and final diff review pass.

## Finish protocol
On `complete`/`finish`, satisfy all criteria and create `docs/road-to-v2/releases/v1.2.md` with `STATUS: COMPLETE`, final commit, migrations, R2/data notes, verification and visual evidence. Push and integrate only when green. Production schema/R2 mutations follow exact backup/migration controls.

## Exclusions
No reusable location entities/images, Catalog PWA, Rapid Catalogue, kits, Staff Directory or Self-Service 2.0. Do not build speculative abstractions for those slices.
