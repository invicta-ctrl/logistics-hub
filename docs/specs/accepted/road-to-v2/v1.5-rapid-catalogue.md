## Objective
Make cataloguing 500+ mixed physical items fast enough for real DOL use. Optimize for walking through cabinets/shelves with a phone or tablet, minimizing repetitive entry while preserving correct per-item behavior. This slice is online-first: it works in the staff workspace over office Wi-Fi. Installable offline use, including the offline staff authorization, follows in V1.6.

## Start gate
Fetch latest main, verify V1.4 completion and bring the branch onto latest main, and confirm the V1.4 location model and V1.2 media pipeline are healthy.

## Core workflow
A staff member starts a **Cataloguing Session** and chooses the physical context, for example `Cabinet 1 → Shelf 2`. Location context remains sticky through the session.

Item behavior is never a locked session default because one shelf may contain loanable, whole-unit consumable and gradual-use/open-unit items together.

For each item show a rapid, tap-friendly choice such as:
- Borrow & return
- Consume
- Use gradually
- Not sure / Review later

The system may suggest a likely value but must not silently persist an uncertain classification.

## Field behavior
**Session-sticky:** current location hierarchy, room/cabinet/shelf and other clearly shared session context.

**Suggested but individually confirmed:** category, item behavior/type, unit, stock area and similar classification fields. Suggestions may use deterministic context such as recent accepted items, existing catalog values and session repetition.

**Always item-specific:** name, primary photo, opening/observed quantity, serial/model when applicable, kit membership and any unique notes.

## Scope
1. Add Start/Resume/Finish Cataloguing Session from an authenticated, phone/tablet-friendly Catalogue entry point in the staff workspace, with durable server-side session state and progress so a session resumes on any signed-in device.
2. Implement capture → save → next with no return-to-table step.
3. Add **Rapid Capture / Review later**: photo + temporary/known name + quantity + location can be captured quickly when classification is unknown. Such records stay clearly incomplete and unavailable to Self-Service/public lending until resolved.
4. Add deterministic suggestions for category/type/unit based on existing values/session context. Suggestions are one-tap confirmations, never opaque automatic decisions.
5. Add duplicate prevention before creating an item using practical signals such as normalized names/aliases, category/model/serial and image hashes where useful. Show possible matches rather than silently merging.
6. Add safe bulk operations for metadata such as move location, assign category, stock area and mark reviewed. Quantity changes remain governed by movement/count workflows, not metadata bulk edits.
7. Support efficient repeated/identical inventory. Allow quantity-based parent records for fungible items and leave room for individually tracked assets only when current requirements justify it; do not force asset-level tracking on ordinary consumables.
8. Make saving resilient while online: each capture saves immediately, and a failed save (for example dropped Wi-Fi) is retried or clearly shown as unsaved, never silently lost. Offline sessions, the offline queue and installability are V1.6; keep the session/save boundary clean enough for V1.6 to take it offline without reworking it.
9. Add efficient keyboard/tablet shortcuts where helpful without compromising touch-first use.

Visual verification must include a realistic long session with mixed item types in one shelf, phone and tablet screenshots, photo capture/preview, suggestion states, duplicate warning, Review-later state, bulk selection and a failed-then-retried save. The agent must inspect rendered screenshots and iterate on tap density, hierarchy, fatigue, accidental-tap risk and speed.

## Acceptance criteria
- Mixed shelves work naturally: sticky location plus per-item type.
- A user can catalog many items without repeated navigation/backtracking.
- Review-later records cannot accidentally appear in public/Self-Service surfaces.
- Suggestions are fast, explainable and never silently authoritative.
- Duplicate warnings reduce accidental duplicate records without blocking legitimate duplicates.
- Bulk metadata operations are safe and auditable.
- Session state, records and photos survive reloads and dropped connections without silent loss, and an interrupted session resumes.
- 500+ item scale remains responsive.
- Required tests, interrupted-connection browser cases, build, privacy scan, accessibility, visual evidence, data/migration verification and final diff review pass.

## Exclusions
No offline mode or offline staff authorization (V1.6), full physical-audit discrepancy session, kit system, Self-Service 2.0 or broad AI classification service. Do not make network AI a dependency for cataloguing.
