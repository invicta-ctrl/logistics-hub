## Objective
Replace repeated free-text storage descriptions with reusable location records and turn “Where is it?” into a practical wayfinding feature for staff and Self-Service, without redesigning all of Self-Service yet.

## Start gate
Fetch latest main, verify the V1.2 completion record, then safely rebase this branch. Stop if the predecessor is incomplete.

## Scope
1. Introduce reusable location entities appropriate to the DOL office. Support a lightweight hierarchy such as Office → Storage Area → Cabinet 1 → Shelf 2 without forcing warehouse-grade complexity.
2. Each location may hold a display name, optional parent, plain-language directions, visibility setting, optional reference image/media key, active status and audit metadata.
3. Associate existing item storage-location values safely. Preserve original values and do not silently combine ambiguous names. Provide reconciliation evidence for any schema/data migration.
4. Add location management to item editing and relevant administration surfaces. Staff should be able to choose an existing location quickly rather than repeatedly type it.
5. Allow one location/reference image to serve many items; do not duplicate the same cabinet photo for every item.
6. Add a polished **Where is it?** action from item/profile surfaces. Show concise directions, hierarchy and the location image when permitted.
7. Add **I can’t find it** and **Location looks wrong** reports as non-destructive attention signals. These reports must never modify quantity or item location automatically.
8. Allow staff to control whether detailed location guidance is shown in Self-Service or kept staff-only.
9. Add location-centric browsing/filtering for staff where it improves organization while preserving existing item filters.

## Visual research and rendered review
Create `docs/visual-research/v1.3.md`. Research wayfinding/location-detail patterns, photo-detail interactions, inventory-location UIs and mobile sheet/dialog patterns using current external references. Record sources, adopted ideas, rejected ideas and reasons.

Capture and visually inspect desktop/tablet/phone renders for location management, item location display, Where-is-it viewer, location photo expansion, missing-image state and report flow. Motion should use fast native transitions and respect reduced motion.

## Acceptance criteria
- Staff can create/reuse/edit/deactivate locations without corrupting item history.
- Existing item location data is preserved or reconciled explicitly.
- Multiple items can point to one location and share instructions/image.
- Where-is-it displays usable directions and imagery where allowed.
- Can’t-find/location-wrong reports create auditable attention records and never alter stock or location themselves.
- Staff-only location details stay staff-only.
- Location search/filtering remains fast for 500+ items.
- Required migration/data verification, tests, build, privacy scan, browser/E2E, accessibility, visual evidence and final diff review pass.

## Finish protocol
On `complete`/`finish`, finish every criterion and create `docs/road-to-v2/releases/v1.3.md` with `STATUS: COMPLETE`, final commit, migrations/reconciliation, permission notes, visual evidence and verification. Integrate only when green and migration controls are satisfied.

## Exclusions
No Catalog PWA, Rapid Catalogue session engine, physical-inventory sessions, kits, Staff Directory, Self-Service 2.0 or intelligent search beyond what this location workflow requires.
