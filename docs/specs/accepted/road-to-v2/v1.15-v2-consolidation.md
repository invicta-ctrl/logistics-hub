# Road to V2 — V1.15 V2 Product Consolidation

STATUS: ACCEPTED BY OWNER FOR IMPLEMENTATION
ROADMAP: Road to V2

BRANCH: `road-to-v2/v1.15-v2-consolidation`
PREDECESSOR: `docs/road-to-v2/releases/v1.14.md` with `STATUS: COMPLETE` on `main`
TARGET MILESTONE: Logistics Hub V2.0 readiness

## Objective
Consolidate V1.1–V1.14 into one coherent product, remove duplicate/dead paths, run realistic user journeys, close quality gaps and produce the evidence required to call the product V2.0. This is a simplification/hardening slice, not a feature dump.

## Start gate
Fetch latest main, verify V1.14 completion and safely rebase. Confirm every prior Road-to-V2 release record V1.1–V1.14 is present on main and no required migration/verification is left unresolved.

## Scope
1. Review the complete information architecture and remove duplicate navigation, obsolete V1 paths, dead UI, legacy code paths made unnecessary by completed Road-to-V2 features and redundant configuration/documentation.
2. Run a terminology/copy consistency pass across Staff, Catalog, Self-Service, Administration, Staff Directory, Kits, Locations, Attention and system states.
3. Review design-system coherence: typography, spacing, cards, dialogs/sheets, status language, images, motion, focus, empty/loading/error states and responsive behavior. Preserve local context where a specialized surface genuinely needs it.
4. Tune animations globally. Keep only motion that improves continuity/feedback; remove jank, gratuitous effects or duplicated transitions. Respect reduced motion everywhere.
5. Validate complete end-to-end journeys using production-like fixture data:
   - first-time Self-Service user;
   - returning borrower and return;
   - staff cataloguing a large mixed shelf;
   - offline Catalog PWA install/use/sync;
   - physical inventory by location with discrepancy;
   - kit inspection/replenishment state;
   - administrator browsing Staff Directory/authorized ID viewer/usage;
   - staff triaging Attention items;
   - global search/command flow;
   - owner checking Administration/system status.
6. Review privacy/retention/permission boundaries across all new media and data domains. Ensure catalog images, location images, transaction evidence and official staff IDs remain clearly separated.
7. Review all migrations and D1/R2 invariants, backup/restore runbooks and production deployment requirements. Reconcile documentation with actual verified production architecture.
8. Run a final code-health pass for maintainability by a beginner/intermediate future maintainer: cohesive modules, plain naming, no unnecessary abstractions, no obsolete compatibility layers, no unused dependencies.
9. Produce final V2 product/reference documentation and migration/operational notes. Update authoritative current/handoff/release records only after verified state matches.
10. Do not invent new V2 features in this slice. Defects/gaps required to make already accepted features coherent are in scope; new capabilities require an amendment.

## Final visual review — mandatory
Create `docs/visual-research/v1.15.md` as the final visual audit. Revisit current external design references rather than assuming earlier research is still sufficient. Capture a systematic screenshot set across desktop/tablet/phone for every major product surface and critical state.

The agent must use its visual capabilities to review the screenshots for hierarchy, alignment, spacing, clipping, image quality, motion continuity, responsive behavior, empty/error/offline states, visual consistency and HAU USC identity. Compare with earlier V1.x evidence and iterate until material visual defects are resolved. Do not approve V2 based on code review alone.

## V2 acceptance criteria
- All accepted V1.1–V1.14 capabilities work together without duplicate/contradictory workflows.
- No known broken/dead navigation or placeholder UI remains.
- Realistic user journeys above pass with documented evidence.
- Performance remains within V1.14 budgets or has explicitly justified measured exceptions.
- Accessibility, reduced-motion and responsive behavior are verified across major surfaces.
- Privacy/permissions/retention for item/location media, evidence and Staff Directory records are verified.
- D1 movement/loan/item invariants remain correct; migrations are reconciled; R2 ownership/cleanup is verified.
- Codebase/documentation is simplified where Road-to-V2 work made older paths obsolete.
- Full relevant unit/integration/browser/offline/accessibility/privacy/build suites pass.
- Final complete diff and repository state are reviewed.

## V2 release record
On completion create `docs/road-to-v2/releases/v2.0.md` with:
- `STATUS: COMPLETE` only if every V2 criterion is green;
- final commit and deployed/verified identity where authorized;
- complete migration level and data reconciliation summary;
- test/build/privacy/accessibility/performance evidence;
- visual audit references;
- backup/rollback/operational notes;
- known non-blocking limitations;
- explicit statement that V1.15 closed the Road-to-V2 milestone.

Update the authoritative current/handoff documentation to identify the product as V2 only after this evidence is true. Do not call it V2 merely because the branch exists.
