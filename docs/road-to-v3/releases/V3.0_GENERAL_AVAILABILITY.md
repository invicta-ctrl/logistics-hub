# V3.0 — General Availability

V3.0 is primarily a **promotion milestone**, not a hidden feature release.

## Required state
- RTV3-09 qualification complete;
- no open reproducible P0;
- production migrations reconciled;
- production deployment verified;
- rollback/recovery references known;
- budgets and observability active;
- accepted product decommissioning complete;
- AI model/provider state re-verified;
- release evidence truthful;
- owner accepts promotion.

## Promotion record
Record:
- V3.0 production commit;
- deployment ID/version;
- schema level;
- current AI role/model mapping;
- known limitations;
- current RPO/RTO proof date;
- supported device/browser matrix;
- release tag/reference;
- owner acceptance.

No new feature is required merely to justify the V3.0 number.

## Decommissioning

V3.0 does not introduce new legacy-retirement work.

All V2 capabilities superseded by Road-to-V3 must already have been decommissioned, redirected, archived, or explicitly retained under the owning RTV3 milestone's accepted spec and release record.

V3.0 promotion must verify:

- no unintended duplicate entry points remain;
- no orphan data/workflow remains;
- retained legacy surfaces are explicitly documented;
- any accepted residual compatibility surface has an owner and retirement condition.

If a required legacy cutover is still incomplete, V3.0 is not ready for promotion.
