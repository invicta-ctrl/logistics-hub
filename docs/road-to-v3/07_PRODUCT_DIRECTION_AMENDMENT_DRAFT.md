# Draft Owner Amendment — Road-to-V3 Product Direction

**Status:** PRE-DRAFT FOR OWNER ACCEPTANCE  

**Product release mapping (2026-10-11):** V2.1 / RTV3-01 prepares this amendment. Acceptance is required before implementation of V2.2 / RTV3-02 and its successors through V2.8 / RTV3-08. The RTV3 IDs are stable internal milestone names, not product V3.x releases. This text remains PRE-DRAFT until separately approved.
**Purpose:** Remove an ownerless future gate. This file is prepared during RTV3-01 so a future DOL administration can review/sign rather than author the direction from scratch.

## Owner decision requested

Authorize Road-to-V3 to introduce the following new domains after **V2.1 (RTV3-01)**:

- Event & Demand Orchestration;
- Resource Promise & Fulfillment;
- Mission Control / Goal Workspace;
- Human Operations extensions to Staff Directory;
- Procurement & Replenishment;
- Lifecycle/Recovery/Zero-Loss;
- Predictive & Preventive Operations;
- Operational Memory & Succession.

## Explicit non-revival rule

This does **not** restore the retired legacy React-era Request Center, procurement/canvassing, deliverables, or old data/control architecture.

The problem domains return only through new current-platform designs using:

- current Workers/D1/R2 stack;
- current identity/authorization;
- current ledger/inventory truth;
- current offline/PWA rules;
- current audit model;
- current Ambient Assist platform;
- current repository governance.

## Request Center statement

The legacy Request Center remains retired.

V2.2 (RTV3-02) introduces a **new Event & Demand Orchestration domain** because the organization still needs a way to express and steward logistics demand. It must not import obsolete UI structure, legacy truth stores, or old coupling.

## AI authorization principle

Road-to-V3 may extend the V2 Ambient Assist architecture into newly accepted domains only through each release's accepted specification.

AI remains:
- deterministic-first;
- advisory;
- bounded;
- privacy-limited;
- human-controlled for consequential actions;
- non-authoritative;
- optional for core operation.

## Decommissioning

Each release that supersedes a current V2 surface must provide a decommissioning plan before cutover.
