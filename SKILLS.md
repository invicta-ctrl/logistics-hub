## Preflight and repair
Inspect actual installed/enabled inventory, discovery and hooks; distinguish missing, disabled, broken, restricted, healthy. Repair affected required capabilities before affected project work using supported official commands and verified sources; verify license, integrity, permissions, dependencies and pinned version, preserve unrelated settings; reload and reverify. No gratuitous upgrades, lookalike packages, bypassing controls/trust prompts, privilege escalation, credentials, paid services, destructive work or untrusted execution. Ask owner when permission, origin, ownership or compatibility unresolved; do not silently substitute or continue affected work. Other hosts may use approved upstream instructions through their supported skill mechanism; do not install Claude solely for another host. See .claude/README for Claude install commands.
Claude: Sonnet executes installs/repairs/skills/tests; Haiku reads static guidance and audits evidence; orchestrator delegates only. Inspect frontmatter and hooks; no skill overrides authority, expands tools or spawns nested agents. Haiku cannot invoke dynamic shell/fork skills; Sonnet executes bounded action, Haiku reviews. Record environment category, plugin IDs/versions, health/repair outcomes and actual applicable invocations (or specific inapplicability reason) in existing evidence; no secret/vault content. No duplicate preflights within unchanged environment.

## Mandatory project kickoff
Run Matt Pocock grilling (grill-me wrapper where available) and dependency-aware questioning before any new-project/substantial implementation; use PLAN.md and verified context, ask only relevant unresolved decisions with recommendations. Run to-spec for specification synthesis, codebase-design for module/seam design, domain-modeling for business rules, to-tickets or wayfinder only if warranted. Verify installed names/instructions, use supported equivalents on other hosts. Use existing accepted spec and owner answers; no unauthorized tracker publication or redundant artifacts. Claude Sonnet prepares questions/plan, Haiku reviews read-only, orchestrator asks owner. Record invocations, resolved decisions, blockers and accepted spec. See AGENTS for acceptance gate.
Lean-ctx, Serena, Context7, ICM and Obsidian are supporting infrastructure as applicable; no broad retrieval. Skill availability is agent-environment preflight, not an application dependency. CI verifies policy presence, not personal plugin installation.
